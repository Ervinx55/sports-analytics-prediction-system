# Dashboard latency and verified explanation backfill

Both frozen models, approval rules, collector schedules and saved forecasts remain unchanged. All new box-score evidence is presentation-only, bound to the exact accepted source-summary ID; superseding that source automatically invalidates the overlay.

Root causes: dashboard read timeouts started after queue admission, so 22 source reads could accumulate multiple twelve-second waits. Health refresh scanned about 287,000 wide extension-owned job-history rows every minute and logs showed 10–17-second executions. The only index on that source is runid; its owner is supabase_admin.

Fix: queue-inclusive eight-second deadlines, abort upstream on expiry, prioritize current market cards and health ahead of historical analytics, and cache only historical calibration reads for sixty seconds. Live decisions/prices are never cached by this change. Schedule fallback runs concurrently instead of adding a second serial network wait. A compact private history table stores only run ID, job ID, status and start/end timestamps. Health refresh copies new IDs and updates nonterminal jobs using the source primary key. No job commands or credentials are copied. Existing health semantics and collector schedules are preserved.

Database verification: completed source rows older than two minutes have zero differences from the monitoring mirror. Updated refresh measured about 403ms versus 10–17 seconds in prior logs. Local live-source dashboard read measured 4.4s cold and 1.1s warm; provider usage is unavailable locally because production secrets are not exported.

Backfill: authorized private probe fetched missing BDL dates and current SGO events. The existing unchanged strict reconciler checks game/team identity, all player mappings, team totals, minute totals and available component statistics. Overlay acceptance also preserves the current accepted team's score and each saved player's points/rebounds/assists/minutes. Original provider packets and frozen-model history remain unchanged. Discrepancies stay rejected.

Implementation review found no blocking issues. Regression checks cover queued expiration, active abort and recovery, bounded concurrency, deduplication and failure release. Hosted checks and CI are required before release.

Migration ordering: the backfill migration was generated by Supabase CLI then renumbered after the already-committed future-dated snapshot migration so fresh rebuilds cannot overwrite the overlay-aware RPC. Only health monitoring and private explanation storage change.
