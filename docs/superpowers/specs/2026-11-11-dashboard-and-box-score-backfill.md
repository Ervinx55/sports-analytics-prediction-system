# Dashboard latency and verified explanation backfill

Both frozen models, approval rules, collector schedules and saved forecasts remain unchanged. All new box-score evidence is presentation-only, bound to the exact accepted source-summary ID; superseding that source automatically invalidates the overlay.

Root causes: dashboard read timeouts started after queue admission, so 22 source reads could accumulate multiple twelve-second waits. Health refresh scanned about 287,000 wide extension-owned job-history rows every minute and logs showed 10–17-second executions. The only index on that source is runid; its owner is supabase_admin.

Fix: queue-inclusive twelve-second deadlines, abort upstream on expiry, prioritize current market cards and health ahead of historical analytics, and cache only historical calibration reads for sixty seconds. Live decisions/prices are never cached by this change. Schedule fallback runs concurrently instead of adding a second serial network wait. A compact private history table stores only run ID, job ID, status and start/end timestamps. Health refresh copies new IDs and updates nonterminal jobs using the source primary key. No job commands or credentials are copied. Existing health semantics and collector schedules are preserved.
