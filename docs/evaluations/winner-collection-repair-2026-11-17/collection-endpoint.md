# Prospective winner collection endpoint

`/api/dashboard?winnerCapture=1` reuses the existing dashboard function slot. Public GET returns aggregate cohort counts and a small latest-run summary. POST requires the configured service secret and accepts exactly `{ "action": "refresh" }` or `{ "action": "settle" }`. Callers cannot supply source URLs, identities, weights, model artifacts, or forecasts.

Refresh retrieves 21 prior Eastern NBA scoreboard dates and today/tomorrow from fixed ESPN URLs, with at most six concurrent NBA requests. A missing or invalid requested date makes NBA history incomplete and prevents NBA forecast capture. Historical HTTP responses are cached in memory for up to six hours with their original receipt times. NFL uses the fixed nflverse games CSV; score-margin baseline inference needs schedule history, not EPA or player-stat downloads. NFL kickoff is round-tripped against the exact Eastern date/time, and source game IDs must match season, week and both teams.

NBA event identity always uses the ESPN event ID. Optional SGO quotes attach only when both canonical team abbreviations and the exact kickoff match one unique provider event. Sportsbook pairs are collected from DraftKings, FanDuel, BetMGM, Caesars, Bovada and Pinnacle through the existing provider budget/cache boundary. A missing quote, suspended quote or partial provider page cannot become complete price coverage. Price availability never changes the independent baseline probability. Conflicting SGO mappings are excluded rather than resolved by response order.

The collector records source URL, original receipt time, raw response and raw-response SHA-256. The source document identity includes URL plus raw-response hash, preventing identical empty responses from different dates from colliding. The database stores later retrieval receipts separately from the content document. Input documents retain their true latest receipt time separately from forecast issue time. One database RPC appends manifests, sources, prospective forecasts and final-result observations atomically. The database assigns capture time and phase, enforcing the five-minute-to-seven-day window and one capture per model/event/phase.

Pregame evidence collection runs alongside quote retrieval within the same source deadline. For NBA games within 24 hours, it matches the official schedule to canonical teams and exact kickoff, archives the official daily-lineup feed, and collects the existing official injury report. Only five explicit Confirmed starter positions per side in a scheduled game can verify; Expected and bench rows cannot. The feed's timezone-less player timestamps remain raw and publication time remains unknown; actual archived receipts prove observation before kickoff. For NFL games within three hours, bounded discovery of official inactive articles records listed names and emergency-QB designations, with incomplete lists labeled partial. This does not infer a complete active roster or starters. The frozen baseline has no injury, lineup, player-defense or rotation adjustment; forecasts remain `BASELINE_ONLY`, `fullFeatureEligible=false`, `productionEligible=false`, and `productionWeight=0`. Injury reports and depth charts are never labeled confirmed starters.

Settlement uses ESPN scoreboard finals or nflverse final score records and names that source explicitly with `sourceAuthority=PROVIDER_REPORTED_FINAL` and `leagueOfficialVerified=false`. A result must match the saved canonical source ID, both team IDs and abbreviations, and original kickoff. Changed identities or starts remain unresolved and are counted as conflicts. Ties are retained explicitly. The saved forecast identity is copied into the outcome only after those checks. Observation time is the source receipt, so a later replay of an old cached result cannot supersede a newer correction. Every pending event attempted is reported to the database queue so unavailable sources cannot starve later events.

Sequential request budgets are 2.5 seconds for pending records, 14 seconds for source collection, and 11 seconds for append, leaving 2.5 seconds within the function limit. A collection deadline aborts source requests and writes no partial forecast batch. An append timeout is explicitly unconfirmed because the database may commit after the caller disconnects; immutable keys make a subsequent retry safe. Logs contain only the failure phase, category, elapsed time and commit status. Exact quote freshness, same-book/same-line checks, model manifests and production gates remain unchanged by the separate suspended-price diagnostic repair.

Validation: the integrated Node suite passed 402 tests; the configured Python environment passed 78 tests. Eight hosted SQL guard groups passed in a rolled-back synthetic transaction, including immutable writes, actual receipt timestamps, backdating rejection, final-result identity, and RLS. The mobile book-comparison browser flow passed. See the release report for final hosted evidence and remaining blockers.
